# 任务书：新增 `kb-index` / `kb-query` 子命令（混合检索知识库，v2）

## 1. 背景与目标

在 `BookerMarkdownTool` 中新增一对子命令：

1. **`kb-index`**：扫描 Markdown 语料，切块后用 **jieba** 分词建倒排 + BM25 统计，用 **sentence-transformers**（模型名由全局 `--emb` 指定）编码建本地向量库，落盘到可增量更新的索引目录。
2. **`kb-query`**：对已建索引执行 BM25 / 向量 / RRF 混合检索，支持人类可读与 `--json` 输出；P2 支持 `--answer` 走 LLM。

设计目标：单机十万级块 P95 < 100 ms（BM25 与向量各 < 50 ms）；索引增量重建；BM25-only 路径零 torch 依赖；命令风格与既有子命令一致。

## 3. 磁盘索引格式

默认 `./.kb-index/`（`--index-dir` 覆盖）：

```
.kb-index/
├── manifest.json        # 见 §4 IndexManifest
├── chunks.jsonl         # 每行一个 ChunkMeta，行序即 chunk_id
├── inverted.jsonl.gz    # 每行 {"term": ..., "postings": [[chunk_id, tf], ...]}
├── bm25_stats.json      # {"N": int, "avgdl": float, "df": {term: int}, "postings_offsets": {...}}
├── vectors.npy          # float32 [N, D]，normalize_embeddings=True，L2 已归一化
└── file_hashes.json     # path -> FileEntry
```

- `manifest.format_version` 不符直接报错提示 `--rebuild`。
- `tokenizer_version` = `f"jieba-{jieba.__version__}-{mode}"`，与 manifest 不一致时 `kb-query` 拒绝加载并提示重建。
- `emb_model` / `emb_dim` 由 `--emb` 与 `model.get_sentence_embedding_dimension()` 写入。
- `vectors.npy` 行序与 `chunks.jsonl` 行序严格对齐；增量写盘时同步重排。
- 目录同存 `inverted.pkl`（pickle，加载更快）时，若其 mtime 不早于 `inverted.jsonl.gz` 则优先读 pickle。

## 4. 数据模型（`kb_models.py`，字段均带 `Field(..., description=...)`）

```python
class ChunkMeta(BaseModel):
    chunk_id: int
    path: str                  # 相对 --src
    heading_path: list[str]
    start_line: int
    end_line: int
    text: str
    n_tokens: int              # jieba 分词后（去停用词）token 数，= dl
    md5: str

class FileEntry(BaseModel):
    md5: str
    mtime: float
    chunk_ids: list[int]

class IndexManifest(BaseModel):
    format_version: int = 1
    tokenizer_version: str
    emb_model: str | None
    emb_dim: int | None
    emb_normalized: bool = True
    created_at: str
    src_root: str
    n_chunks: int
    files: dict[str, FileEntry]

class QueryHit(BaseModel):
    chunk_id: int
    path: str
    heading_path: list[str]
    start_line: int
    end_line: int
    snippet: str
    bm25_score: float | None
    vec_score: float | None
    fused_score: float
    ranks: dict[str, int]      # {"bm25": 3, "vec": 11}

class QueryResult(BaseModel):
    query: str
    mode: str
    emb_model: str | None
    hits: list[QueryHit]
    answer: str | None = None
```

## 5. 核心算法（`kb_core.py`）

### 5.1 分词器 `Tokenizer`（jieba）

```python
class Tokenizer:
    def __init__(self, mode="search", stopwords=None, user_dicts=None):
        import jieba
        jieba.setLogLevel(20)  # 屏蔽 "Building prefix dict" 日志
        for p in user_dicts or []:
            jieba.load_userdict(p)
        ...
    def tokenize(self, text) -> list[str]:
        # search 模式：jieba.lcut_for_search(text)；cut 模式：jieba.lcut(text)
        # 后处理：strip() 丢弃空白；全标点 token 丢弃；纯英文/数字小写化并保整词；
        #        去停用词（停用词表来自 util.asset("kb_stopwords_zh.txt")）
```

- 默认 `mode="search"`（`lcut_for_search`），长词同时切出短词，利于召回；`--tokenizer cut` 可切回精确模式。
- 英文与数字：jieba 已能整体切出，统一 `lower()`；不再加 `c:` / `w:` 前缀。
- 停用词：默认读内置表，`--stopwords PATH` 覆盖，`--no-stopwords` 关闭。
- **不做单字过滤**（jieba 的 `cut_all=False` 已足够），但可选 `--min-token-len 1`。
- 初始化成本约 0.3–0.8 s（首载词典），进程内**单例复用**；`--workers > 1` 时用 `initializer` 在每个子进程各自初始化，注意不要把 jieba 对象跨进程传递。
- `version` 属性返回 `f"jieba-{jieba.__version__}-{mode}"`，写入 manifest。

### 5.2 倒排 + BM25 `BM25Index`

- 建索引用 jieba 原始词频 `tf` 与 `dl = len(tokens)`，写 `inverted` + `bm25_stats`（含 `N`、`avgdl`、`df`）。
- 打分（`k1=1.5`、`b=0.75` 可配）：

```
IDF(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
score(q,d) = Σ_{t∈q∩d} IDF(t) * tf(t,d)*(k1+1) / (tf(t,d) + k1*(1 - b + b*dl/avgdl))
```

- 查询侧对 query token 去重后逐 term 取 posting；十万级块全量驻留内存（< 200 MB）允许，配 `postings_offsets` 支持按需 seek。

### 5.3 向量层 `VectorStore` + `Encoder`

**Encoder 抽象（关键，保证可测试、可惰性导入）**：

```python
class Encoder(Protocol):
    name: str
    dim: int
    def encode(self, texts: list[str], batch_size=64, show_progress=False) -> np.ndarray: ...

class STEncoder:                     # 仅在此处 import sentence_transformers
    def __init__(self, model_name_or_path: str, device: str | None = None):
        from sentence_transformers import SentenceTransformer
        self.model = SentenceTransformer(model_name_or_path, device=device)
        self.dim = self.model.get_sentence_embedding_dimension()
    def encode(self, texts, batch_size=64, show_progress=False):
        return self.model.encode(
            texts, batch_size=batch_size, normalize_embeddings=True,
            convert_to_numpy=True, show_progress_bar=show_progress)

class FakeEncoder:                   # 测试用：hash → 固定维度向量，确定性
    ...
```

- 模型名**只来自全局 `--emb`**（其次 `EMB_MODEL_PATH`）；`--emb` 为空且未给 `--no-emb` 时 `kb-index` 报错：
  `错误：未指定 embedding 模型。请用全局参数 --emb <模型名或本地路径>，或加 --no-emb 仅建 BM25 索引。`
- `--emb` 支持 HF 模型名（`BAAI/bge-small-zh-v1.5`）或本地路径；离线场景设 `HF_HUB_OFFLINE=1` 或直接传路径。
- 新增 `--device {cpu,cuda,mps,auto}`（默认 `auto`，仅作用于 embed 阶段）、`--emb-batch-size`（默认 64）。`verbose` 时打印模型名/维度/device/编码耗时。
- CPU 场景建议 `torch.set_num_threads(max(1, cpu_count//2))`，避免与读文件线程争抢。
- 归一化 + 内积 = 余弦；`semantic_search` 等价于 `vectors @ q_vec`，直接矩阵乘实现，不引入索引结构。
- **惰性导入**：`kb_query.py` 在 `--mode bm25` 或 manifest 无 `emb_model` 时，全程不 import `sentence_transformers` / `torch`；`kb-index --no-emb` 同理。测试用 `sys.modules` 断言未被导入。
- 预留 `--vector-backend {numpy,faiss}`（P2，faiss 用 `IndexFlatIP`），接口保持在 `VectorStore`。

### 5.4 切块 `ChunkSplitter`

- 复用 `util.split_md_lines` / `util.group_chunks`；按 `#`~`######` 分段并维护 `heading_path`；段内按段落聚合到 `--chunk-size`（默认 800 字符），`--chunk-overlap`（默认 100）滑动重叠；超长段按句子边界（。！？；\n）硬切。
- 过滤：`< --min-chunk-len`（默认 30）丢弃；纯代码块（连续 ≥3 行 fenced 且无解释文字）默认丢弃，`--keep-code` 保留。
- 默认排除 `.git/`、`node_modules/`、`index/`，`--exclude GLOB` 可重复追加。

### 5.5 混合融合 `HybridRetriever`

- `--mode {bm25,vec,hybrid}`（默认 `hybrid`）；单路先取 `candidate_n = max(topk*5, 50)`。
- 默认 **RRF**：`fused(d) = Σ_r 1/(rrf_k + rank_r(d))`，`--rrf-k` 默认 60。
- 备选 `--fuse weight`：各路 min-max 归一化后 `alpha*bm25 + (1-alpha)*vec`，`--alpha` 默认 0.5。
- 输出保留各路原始分与 rank，便于调参。

## 6. 命令参数

> `--emb`、`-m/--model`、`-k/--key`、`-H/--host` 已在 `__main__.py` 顶层定义。两个子命令**不重新设默认值**，而是以
> `parser.add_argument("--emb", default=argparse.SUPPRESS, help="...")`
> 再次暴露，使 `md-tool --emb X kb-index ...` 与 `md-tool kb-index ... --emb X` 均可，且不给值时不会覆盖顶层值。

### `kb-index`

```
kb-index SRC...                     # 目录递归 *.md，或直接给文件
  --index-dir PATH      (默认 ./.kb-index)
  --chunk-size INT      (800)
  --chunk-overlap INT   (100)
  --min-chunk-len INT   (30)
  --keep-code
  --exclude GLOB        (可重复)
  --tokenizer {search,cut}   (search)
  --stopwords PATH / --no-stopwords
  --user-dict PATH      (可重复，jieba.load_userdict)
  --emb MODEL           (全局参数；为空且未 --no-emb 则报错)
  --no-emb              (只建倒排 + BM25)
  --emb-batch-size INT  (64)
  --device {auto,cpu,cuda,mps}   (auto)
  --workers INT         (默认 cpu_count；仅用于读文件/切块并行，embedding 走 encoder 内部批处理)
  --incremental         (默认开；按 file_hashes.json 的 md5 跳过未变文件)
  --rebuild
  --prune / --no-prune  (默认 prune：删除已消失文件的块)
  --stats
  -v/--verbose
```

### `kb-query`

```
kb-query QUERY                     # 或 -q/--query
  --index-dir PATH      (默认 ./.kb-index)
  -n/--topk INT         (10)
  --mode {bm25,vec,hybrid}   (hybrid)
  --fuse {rrf,weight}   (rrf)
  --rrf-k INT           (60)
  --alpha FLOAT         (0.5)
  --candidate-n INT     (0 = 自动)
  --emb MODEL           (全局参数；与 manifest.emb_model 不一致则报错)
  --device {auto,cpu,cuda,mps}
  --emb-batch-size INT  (64)
  --context INT         (0；>0 输出命中块前后各 N 行原文)
  --snippet-len INT     (200)
  --json                (stdout 仅 JSON，日志走 stderr)
  --answer              (P2；需 -m/-k/-H，复用顶层 LLM 参数)
  -v/--verbose
```

**输出示例**：

```
[1] 0.0328  docs/llm/rag.md  › 检索增强 › 混合检索  L120-168
    ...BM25(3) Vec(11)  jieba 分词后倒排与向量召回经 RRF 融合……
```

**错误提示**（关键几条）：

- 索引不存在 → `未找到索引：{dir}。请先运行 kb-index。`
- `emb_model` 不匹配 → `索引使用的 embedding 模型为 {a}，当前 --emb 为 {b}；请改用相同模型或 --rebuild 重建。`
- `--mode vec/hybrid` 但 manifest 无向量 → `该索引未包含向量层（建索引时使用了 --no-emb）。请用 --mode bm25，或带 --emb 重建索引。`

## 7. 工作流

`kb-index`：`scan_files → diff_against_manifest(md5) → split_chunks → jieba tokenize → build postings/BM25 → encode(可选) → 合并旧块 → 写盘 → 写 manifest → --stats`

`kb-query`：`load manifest（校验 format_version / tokenizer_version / emb_model）→ load chunks & bm25 →（需要时）load vectors + 构造 STEncoder → query 分词 → BM25 topN ∥ 向量 topN → 融合 → QueryHit → 输出（可选 --answer）`

增量要点：新块追加分配 `chunk_id`；被删文件对应块在写盘时压缩重排 id，并同步重写 `vectors.npy` 行序与 postings 中的 id；`--rebuild` 走全量路径（清空目录）。

## 8. 依赖与兼容

- `requirements.txt` 追加：`jieba`、`numpy`、`sentence-transformers`（会拉入 `torch`、`transformers`、`huggingface-hub`）。
- 由于 torch 体积大：**必须保证 `--no-emb` / `--mode bm25` 完全不 import `sentence_transformers` 与 `torch`**，并在 README/`--help` 中说明。
- 环境变量：`EMB_MODEL_PATH`（作为 `--emb` 缺省时的回退）、`HF_HOME` / `HF_HUB_OFFLINE`（模型缓存与离线）、`SENTENCE_TRANSFORMERS_HOME`。
- 模型缓存首次下载需联网；纯离线部署建议传本地模型目录路径。
- Python ≥ 3.10；路径统一 `pathlib`，Windows 兼容（注意 jieba 在 Windows 下多进程需 `if __name__ == "__main__"` 保护，`kb-index` 的 `workers` 实现需遵循）。

## 9. 验收标准

1. `docs/` 下约 500 篇 md 全量 `kb-index --emb BAAI/bge-small-zh-v1.5` 成功；`--stats` 输出块数、词项数、维度、device、编码耗时、磁盘占用；重复执行（无变更）5 s 内完成并提示「0 文件更新」。
2. 修改 1 个文件后 `--incremental` 仅重建其块，`n_chunks` 正确增减，`chunks.jsonl` 与 `vectors.npy` 行数一致。
3. `kb-query "混合检索"` top3 命中含该词的块；`--mode bm25` 与 `--mode vec` 结果不同且均非空；`--mode hybrid` 的 `ranks` 同时含两路。
4. jieba 生效验证：`Tokenizer("search").tokenize("知识库检索增强")` 输出含「知识」「检索」「增强」等切分结果（用固定断言写进单测）；`--tokenizer cut` 结果与 search 模式不同。
5. `--json` 输出可 `json.loads` 且符合 `QueryResult`；`--json` 时 stdout 只含 JSON。
6. **无 torch 环境**（测试中用 `sys.modules["sentence_transformers"] = None` 模拟）下 `kb-index --no-emb` 与 `kb-query --mode bm25` 正常工作。
7. `--emb` 与索引不一致时给出 §6 的错误提示；`--emb` 写在子命令前后均可生效（两种位置各写一条 CLI 测试）。
8. `--rebuild` 与删除重建结果一致（`chunks.jsonl` diff 为空）。
9. 单测覆盖：jieba 分词断言、BM25 手算样例、RRF 排序、增量 diff、`FakeEncoder` 下向量检索与融合；`pytest` 全绿。
10. `kb-index --help` / `kb-query --help` 与现有子命令风格一致（中文 description，参数分组清晰）。
